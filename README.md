# 大富翁抽籤・命運加強版

課堂抽籤工具，支援多班名單、學生 GIF 頭像提交、教師審批，以及每班持續中籤統計。

本專案基於 DigitalTeacherHK 的[大富翁抽籤](https://sites.google.com/view/digitalteacherhk-monopoly)改良。沿用原專案的版權說明：版權屬原作者 DigitalTeacherHK 所有；原庫未提供獨立 LICENSE，本次沒有另行指定開源授權。

## 已加入的功能

- 移除排除學生名單，全部在用學生均可被抽中。保留擲兩顆骰子及快速抽籤。
- 教師密碼登入；新增、改名、封存班別；按學號批量編輯學生。
- 原有 32 位學生首次啟動時匯入「原有班別」，可在後台改成實際班名。
- 同名學生用學號區分；頭像與紀錄以內部 ID 關聯。
- 每位學生獨立的頭像提交連結，可逐個產生、全班匯出 CSV 或停用；7 天過期。
- 接受 GIF、PNG、JPEG、WebP，最多 5 MB。每幀最多 4096 × 4096、最多 300 幀，總像素上限 2500 萬。
- GIF 以原檔保存，保留動畫。教師批准後才會出現在棋盤；可拒絕／刪除。
- 每班自動沿用一份記錄，持續累計中籤次數，包含零次學生，支援 CSV 匯出。
- 機會及命運內容可在後台逐項編輯（分號及空行分隔）；抽到特殊格後，下一抽必定抽中學生。
- 抽籤由伺服器產生、記錄；同一請求重試只記一次。結果視窗／動畫只是已記錄結果的呈現。

「所有人均可被抽中」代表沒有黑名單。保留原有棋盤移動規則：擲骰子從目前位置向前走，並不是每一抽均對全班作等機率獨立抽樣。下一抽必須是學生時，會跳過特殊格，介面會說明額外步數。中籤者仍可重複中籤。

## 本機開始使用

需要 **Node.js 24 或以上**。

```sh
npm ci
npm start
```

1. 在終端找到「首次設定代碼」。
2. 開啟 <http://localhost:3000/admin.html>，輸入代碼，建立至少 12 字元的教師密碼。
3. 在「班別與名單」新增班別，選班後加入學生，或使用「匯入 Excel」大量加入。可搜尋姓名、原班別或學號。
4. 按「開始抽籤」，或返回前台選班。無需建立或結束課堂。
5. 於「班別與名單」產生學生專屬連結，個別交給本人；學生提交後到「頭像審批」批准。
6. 下次選擇同一班，會延續原有棋盤及統計。舊版本各課堂的明細會在啟動時自動合併至所屬班別；舊棋盤網址仍可使用。

預設只允許本機連線。若要同一 Wi-Fi 的手機試用，可在終端設定 `HOST=0.0.0.0` 後啟動，並用電腦的區域網絡 IP 開啟後台及產生連結；`localhost` 連結不能交給另一部裝置。對外使用請部署 HTTPS 版本。

本機資料在 `data/monopoly.sqlite`（含頭像）；沒有使用瀏覽器 localStorage 儲存名單或統計。教師登入有效 12 小時。測試資料使用獨立暫存資料庫，不會改動正式資料。

### Excel 名單大量匯入、匯出及小規模更新

「班別與名單」上方的「匯入 Excel」會開啟匯入視窗，提供預覽和空白範本。左方可匯出全部名單；選班後亦可只匯出該班。單位學生修改可直接按「編輯」，保留頭像和身份；「更多管理」提供批次文字編輯及班別設定。

使用一張工作表，第一列為 `GROUP | CLASS | NO | 中文姓名`（四個獨立欄位）。`GROUP` 對應系統班別；例如 GROUP=ICT、CLASS=4A、NO=1、中文姓名=陳同學，會加入 ICT，前台顯示 **4A 1 陳同學**。同一 GROUP 內，不同 CLASS 可有相同 NO。

1. 選取 `.xlsx` 後按「讀取並預覽」。畫面列出各行、新增／更新／保持／移出的人數及資料錯誤。
2. 檢查後按「確認套用匯入」，整批資料會一起儲存；有錯誤的檔案不會部分匯入。
3. 小規模修改時，先匯出 Excel，修改四個可見欄位後重新上載。檔案另有隱藏的學生識別欄，請保留，讓改名、改 CLASS／NO、調 GROUP 後仍維持同一學生的頭像與紀錄。新增學生請新增一行，不要複製舊學生的隱藏識別碼。

預設「新增及更新」保留未列在檔案的學生。若選「同步涉及班別」，只會把**檔案中出現的 GROUP** 裏未列出的學生移出；其他 GROUP 不受影響。移出會停用提交連結，抽籤紀錄仍保留。更改 GROUP 後，歷史中籤次數仍歸屬原來的 GROUP。

無識別欄的初次檔案以 GROUP＋CLASS＋NO 配對，再次匯入不會新增副本。若要更改這些欄位，請使用系統匯出檔案。預覽有效 10 分鐘；預覽後如有人更改名單，系統會要求重新預覽，避免覆蓋新資料。

支援大小 5 MB 以內的 `.xlsx`，每個檔案最多 5,000 位、每個 GROUP 最多 100 位。NO 使用 1–9999 整數。舊有未設定 CLASS 的學生可從匯出檔案重新匯入；新匯入資料則須填 CLASS。欄位只接受文字及數值，公式需先貼上為值。

### 跨裝置介面及班別統計

電腦使用原有環形棋盤；平板及手機（視窗寬度 1024px 或以下）亦保留環形棋盤，按寬度調整每邊格數；較長棋盤可上下捲動，中央抽籤控制區會保持可用。後台表單、圖表及名單會隨畫面換行，毋須手動縮放。

在「班別統計」選擇班別後，可切換：

- **累積全部紀錄**：沿用這個班別的持續記錄，顯示各學生累積中籤次數及各月份次數。
- **每月統計**：選擇月份，顯示這個月的學生中籤次數及每日次數。
- **每週統計**：選擇週內任一天，系統自動計算該週星期一至日，顯示學生及每日次數。

所有日期以香港時間（UTC+8）計算。畫面同時提供長條圖、學生名單、零次中籤、抽籤明細及 CSV 匯出；封存班別也可查看。機會及命運次數另外計算，不會加入學生中籤次數。

在「機會與命運」每項以 `；` 結尾，項目之間留一空行。可用「整理分行與分號」自動統一格式。支援半形 `;`、全形 `；` 及舊式逐行貼上；儲存後會整理成分號加空行格式。

### 音效管理

在後台「音效管理」搜尋、試聽及勾選音效，按「儲存勾選」套用；預設全部選用，新加入音效亦會預設選用。勾選儲存在伺服器，相同來源的已開啟棋盤會收到設定更新。全部取消後只停用抽籤音效，背景音樂仍由前台音效開關控制。

來源為 [memes.tw 迷因音效板](https://memes.tw/sound)。使用 `npm start` 啟動時會自動同步全部分頁，之後成功每 6 小時更新；失敗按 1、2、4、8、16、24 小時退避重試，最多每天一次。無需開啟瀏覽器或後台，設定 `SOUND_AUTO_SYNC=false` 可停用。最後嘗試時間、失敗次數保存在資料庫，重啟會沿用排程，逾期則補跑。每次同步同時保留使用者原有勾選，只有完整讀取成功才會替換清單。來源連線不佔用抽籤資料庫請求佇列。

**目前限制：**2026-10-19 本機後端取得來源時遇到 Cloudflare HTTP 403。內附 2026-10-19 透過正常瀏覽器讀取 32 個公開分頁取得的 1,135 項不重複音效清單；音效本身從來源的公開媒體網址直接播放，沒有重新上載原檔。更新失敗時後台會顯示原因及清單取得時間，並保留清單與勾選，不會假裝已同步全站。來源恢復接受伺服器讀取後，下次排程可自動更新；沒有繞過來源驗證。**本次瀏覽器逐頁讀取全站清單成功；伺服器定時同步仍未成功，定時重試不代表已解決 403。** 要持續無人操作地讀取，仍需站方提供音效 API／匯出 feed，或允許伺服器正常讀取。遠端媒體不可用時試聽／前台會顯示播放失敗。

排程只在伺服器運行時執行。本機關機、程式停止，以及 Render Free 休眠期間不會執行；啟動／喚醒後會檢查資料庫並補跑逾期工作。全天候更新需要持續運行的執行環境；目前沒有部署常駐雲端 worker。

中籤視窗使用本機 Canvas 彩炮，不依賴第三方動畫 CDN；尊重系統減少動態效果設定。頭像在手機與電腦結果視窗均放大顯示。

### 名單編輯及統計

同一班內學號須唯一。同一個人保持相同學號會保留頭像和身份；換人時請用新學號，避免把兩個人的紀錄合併。名單移除不會刪除既有抽籤紀錄；學生連結會停用。封存班別會暫停其抽籤並停用所有連結，歷史統計仍可查閱。

統計顯示目前在用學生及曾在該班中籤的已移出學生；抽籤明細保留中籤當時的姓名、學號和事件內容。名單及事件編輯影響之後的抽籤；棋盤會在每次抽籤時取得最新學生資料，亦可重新選班載入。

連結相當於該學生的提交通行證，請個別派發。重新產生會即時使舊連結失效。每位學生最多保留一張待審、一張已批准頭像；新待審不會取代已批准的圖，直到教師批准。刪除批准圖後會回到預設貓咪。

## Render + Neon 部署

已備妥 `render.yaml`，使用 Render Node.js Web Service，並把資料和圖片存入 Neon PostgreSQL。**Render 沒有 DATABASE_URL 會拒絕啟動**，防止誤把正式資料寫入暫存 SQLite。

1. 把此版本原始碼及 `package-lock.json` 放回 GitHub 專案（不要上傳 `.archive/`、`data/`、`node_modules/` 或 `.env`）。
2. 在 Neon 建立資料庫，從 Connect 複製 PostgreSQL connection string，保留 `sslmode=require` 等 TLS 參數。
3. 在 Render 以 Blueprint 連接本庫、採用 `render.yaml`，選 Free，將連線字串填入秘密環境變數 `DATABASE_URL`。請勿把連線字串寫進 GitHub 或前端。
4. 等候部署完成，開啟 Render 的 HTTPS 網址及 `/admin.html`。從 Render Logs 取首次設定代碼，再建立教師密碼。
5. 建立班別和學生連結；手機直接使用 Render 網址上的個人連結。

資料表會在啟動時建立。正式啟動設定：

| 環境變數 | 用途 |
| --- | --- |
| `DATABASE_URL` | Neon PostgreSQL 連線字串，只放 Render secret |
| `HOST=0.0.0.0` | Render 對外監聽 |
| `PORT` | 由 Render 提供，預設 3000 |
| `COOKIE_SECURE=true` | HTTPS 登入 Cookie |
| `APP_ORIGIN` | 自訂網域時填完整 HTTPS origin；未填會使用 `RENDER_EXTERNAL_URL` |
| `DATA_DIR` | 只供本機 SQLite 模式指定資料目錄 |

Render 的 Free 服務閒置會休眠，重啟後暫存磁碟資料不會保留，所以正式資料全部放 Neon。開課前先開網站，留時間喚醒。頭像佔用 Neon 儲存空間，免費額度以實際帳戶控制台為準。

參考：[Render 免費服務說明](https://render.com/docs/free)、[Neon 連線設定](https://neon.com/docs/connect/connect-from-any-app)。

### GitHub Pages 入口（可選）

為避免跨網站登入 Cookie 被瀏覽器封鎖，完整程式、後台和學生上載頁由 Render 同一個 HTTPS 網域提供；GitHub Pages 保留為公開入口，按一下即可前往。GitHub Pages 本身不能執行 Node.js API。

1. 在 GitHub → Settings → Secrets and variables → Actions → Variables 新增 **Repository variable** `RENDER_APP_URL`，填 Render 根網址，例如 `https://your-app.onrender.com`，不含路徑。
2. GitHub → Settings → Pages 的 Source 改為 **GitHub Actions**。
3. 在 Actions 手動執行 **Publish classroom entry on GitHub Pages**。
4. 原來 `https://yuenhk.github.io/Monopoly_Fate10/` 將成為新的入口頁。此工作流程只發佈產生的 `pages-dist/`，不會發佈後端原始檔或本機資料。

Pages 發佈流程刻意使用手動觸發；設定好 Render 之後才切換既有入口。測試 workflow 會在 main push 及 pull request 執行。Render 更新可由其 GitHub 自動部署設定管理。

## 專案架構

```text
index.html / app.js / board.css  課堂棋盤
admin.html / admin.js            教師後台
student.html / student.js        學生個人頭像提交
shared.js / ui.css               共用介面及 API 呼叫
server.mjs                      登入、名單、上載審批、班別抽籤及統計 API
class-records.mjs               舊課堂合併及每班唯一記錄遷移
database.mjs              本機 SQLite／雲端 PostgreSQL adapter
game.mjs                        棋盤生成及骰子／跑馬燈規則
statistics.mjs                  香港時間的週／月範圍及統計時間序列
event-format.js                 事件分號及空行格式解析
roster-workbook.mjs              Excel 名單解析、匯出及更新預覽
student-identity.js              CLASS／NO 及顯示 ID
sound-library.mjs                音效清單解析及完整分頁更新
sound-catalog.json               公開來源清單備份（32頁、1135項；不含音效檔）
celebration.js                   中籤視窗內的本機 Canvas 彩炮
legacy-roster.json              匯入原有名單
sound/、video/                   沿用原有視聽素材
render.yaml                     Render 部署設定
.github/workflows/              測試及 Pages 入口部署
```

API 的班別、名單、課堂、統計和頭像審批皆要求教師登入；學生只可持個人 token 讀取自己的提交狀態及提交圖片。未審頭像只有教師可讀，批准圖片以不可猜測的 UUID 路徑提供。伺服器只會對外提供明確列出的網頁和媒體檔案。

## 驗證

```sh
npm test
```

測試同時使用 SQLite 及本機 PGlite PostgreSQL 核心，驗證登入與權限、班別及同名學生、學號穩定性、動畫 GIF 原檔保存及審批、連結重設／停用、無排除名單、特殊事件規則、重試與並行請求不重複計數、每班持續統計、舊記錄合併、學生逐位修改、封存及本機重啟持久化。

PGlite 測試不是實際 Neon／Render 的部署測試；上線仍須核對資料庫連線、HTTPS 登入及手機跨裝置上載。

原版 `index.html` 和 README 可在本機 `.archive/` 找到；備份不公開部署。
